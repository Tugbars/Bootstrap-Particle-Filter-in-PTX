01 — The Problem

Why Online Parameter Learning Is Hard

Stochastic volatility (SV) models describe how an asset's return variance evolves over time through a latent process. The standard formulation introduces a hidden log-variance ht that follows an autoregressive process governed by static parameters — persistence ρ, volatility-of-volatility σz, mean level μ, and baseline noise σbase.

The core challenge: both the latent states and the parameters that govern their dynamics are unknown. A particle filter can track latent states given known parameters, and MCMC can sample parameters given the full state trajectory. But doing both simultaneously and online — updating after every single observation without revisiting old data — requires a fundamentally different approach.

Naïvely adding parameters to the particle filter state vector leads to rapid degeneracy. Parameters are static — they don't have process noise to rejuvenate diversity. After a few resampling steps, all particles collapse onto a single parameter value. The filter becomes overconfident and wrong. This is the well-known particle depletion problem for static parameters in sequential Monte Carlo.

The solution is SMC² (Sequential Monte Carlo Squared) — a particle filter within a particle filter. The outer layer maintains a population of parameter hypotheses. Each hypothesis runs its own inner particle filter to estimate the latent states. When the outer population degenerates, a Metropolis-Hastings rejuvenation move proposes fresh parameters and verifies them by replaying the inner filter. Our implementation combines three specific innovations that, together, create a system significantly more capable than any of these components alone.

02 — The Generative Model

Regime-Switching Stochastic Volatility

The model uses a transformed latent regime variable z̃t that drives nonlinear curves for the mean, variance, and mean-reversion speed of log-volatility. This creates rich regime-switching dynamics from a single latent AR(1) process.

Latent regime dynamics z̃t = ρ · z̃t-1 + σz · εt εt ~ N(0, 1) zt = 1.5 · (1 + tanh(z̃t)) squash to [0, 3] Regime-dependent curves (parameterized by z) μ(z) = μ_base + μ_scale · (1 − e−μ_rate · z) σh(z) = σ_base + σ_scale · (1 − e−σ_rate · z) θ(z) = θ_base + θ_scale · (1 − e−θ_rate · z) Log-volatility transition ht = (1 − θ(z)) · ht-1 + θ(z) · μ(z) + σh(z) · ηt ηt ~ N(0, 1) Observation (OCSN linearization via log y²) yt = eht/2 · νt νt ~ N(0, 1) obst = log(yt²) ≈ ht + log(χ²(1)) linearizes the observation

The four learned parameters are θ = (ρ, σz, μbase, σbase), while the curve shapes (scale, rate terms) and the θ(z) speed curve are fixed offline. The log-squared transform converts the nonlinear observation model into an approximately linear-Gaussian one, enabling Kalman-like sufficient statistics inside the inner filter — this is the OCSN (Omori-Chib-Shephard-Nakajima) linearization.

03 — The Three-Layer Architecture

SMC² with RBPF Inner Filter and CPMMH Rejuvenation

The algorithm operates as three nested layers, each solving a distinct inference problem. The outer layer tracks what the parameters are. The inner layer tracks what the latent states are given those parameters. The rejuvenation layer refreshes parameter diversity when it collapses.

Layer 1 — Outer
SMC² Particle Filter over θ
Maintains Nθ = 1024 parameter particles, each a hypothesis about (ρ, σtotal, μbase, r). Each particle carries a weight proportional to how well its inner filter predicted the data so far. When the Effective Sample Size (ESS) drops below 50%, trigger systematic resampling followed by CPMMH rejuvenation.
Layer 2 — Inner
Rao-Blackwellized Particle Filter
For each θ-particle, runs Ninner = 512 inner particles tracking the latent regime z̃t. Given z̃, the log-volatility ht is conditionally linear-Gaussian, so Kalman sufficient statistics (μh, Vh) are propagated analytically instead of sampled. This Rao-Blackwellization dramatically reduces variance compared to a full bootstrap filter.
Layer 3 — Rejuvenation
Correlated Pseudo-Marginal MH (CPMMH)
When the outer filter resamples, duplicate θ-particles need diversification. CPMMH proposes θ* near the current θ, then replays the inner RBPF from a fixed-lag checkpoint using correlated noise (ρcorr = 0.99). The high correlation ensures the proposed and current log-likelihoods are similar, yielding acceptance rates of 25–40% — far higher than uncorrelated PMMH.
Innovation
(σtotal, r) Reparameterization
Instead of learning σz and σbase directly, learns their polar decomposition: σtotal = √(σz² + σbase²) and r = σz/σtotal. This aligns CPMMH proposals with the likelihood geometry, breaking the identification ridge between the two volatility channels.

Standard SMC² uses a bootstrap particle filter as the inner filter and standard PMMH for rejuvenation. Our implementation replaces the inner filter with an RBPF (exploiting the conditional Gaussianity of ht | z̃t) and replaces PMMH with CPMMH (using correlated noise to keep acceptance rates high). These aren't independent improvements — they compound. The RBPF provides tighter likelihood estimates, which makes the CPMMH log-likelihood ratio less noisy, which further improves acceptance rates.

04 — The Algorithm, Step by Step

Per-Tick Update Cycle

Every time a new observation yt arrives, the following sequence executes. The entire pipeline runs on a single CUDA stream with minimal host synchronization.

Store noise for CPMMH replay
Draw and store the random variates (z-noise for regime transitions, u-noise for resampling) in a circular buffer. These will be needed if rejuvenation replays this timestep later. The buffer wraps at L + 64 slots where L is the fixed lag.
Inner RBPF propagation (all Nθ × Ninner particles)
For each inner particle: propagate z̃ via the OU transition, compute regime-dependent curves μ(z), σh(z), θ(z), then run the Kalman predict-update for (μh, Vh). Compute the observation log-likelihood ℓt = log p(yt | z̃t, θ) under the OCSN Gaussian approximation. Update inner particle weights.
Inner conditional resampling
Within each θ-particle's inner cloud: compute ESS. If ESS/Ninner drops below threshold, resample inner particles via systematic resampling and reset weights. This maintains diversity in the latent state estimates.
Accumulate outer log-likelihood
Each θ-particle's outer weight is updated by the log-marginal-likelihood increment: the log of the normalizing constant from step 2. This is simply log(Σi wi) summed across inner particles — the particle filter's unbiased estimate of p(yt | y1:t-1, θ).
Outer ESS check and resampling
Compute outer ESS over the Nθ parameter particles. If ESS < 0.5 · Nθ, trigger systematic resampling of θ-particles (duplicating good ones, dropping poor ones), then immediately run Krejuv = 5 rounds of CPMMH to diversify the duplicates.
CPMMH rejuvenation (if triggered)
For each θ-particle in parallel: propose θ* via a random walk (95% adaptive covariance, 5% fixed for ergodicity). Derive physical σz* and σbase* from the proposed (σtotal*, r*). Replay the inner RBPF from the checkpoint at t - L using correlated noise: ε* = ρcorr · εcurrent + √(1 - ρcorr²) · εfresh. Accept or reject via the standard MH ratio using the replayed vs. current log-likelihoods.

05 — The Identification Ridge

Why σz and σbase Are Unidentifiable

The stochastic volatility model has two channels through which randomness enters the log-volatility ht: the regime innovation σz (which drives z̃ transitions) and the direct volatility noise σbase (which enters the h transition directly). The data constrains their combined effect — the total vol-of-vol — but cannot distinguish which channel delivers it.

Likelihood surface in (σz, σbase) space

The likelihood surface forms a narrow valley (ridge) along the curve σz² + σbase² ≈ constant. Moving along this valley barely changes the likelihood. Moving perpendicular to it changes it dramatically. But MCMC proposals in the original (σz, σbase) coordinate system don't know the valley exists.

A random perturbation like (+0.02 to σz, +0.01 to σbase) moves mostly perpendicular to the valley. The likelihood drops. Rejected. A perturbation like (+0.02 to σz, −0.015 to σbase) happens to move along the valley. Accepted. But that specific combination is rare in a random 4D walk — the proposal doesn't know the valley exists. Out of 5 CPMMH moves, maybe 0–1 align with the valley by accident. Most proposals are wasted fighting the geometry.

06 — The Reparameterization

Breaking the Ridge with (σtotal, r)

Instead of learning the raw parameters (σz, σbase), we learn their polar decomposition:

What we learn (well-conditioned) σ_total = √(σz² + σbase²) total vol-of-vol — WELL IDENTIFIED r = σz / σtotal split ratio ∈ (0, 1) — weakly identified How to recover physical parameters σz = r · σtotal σbase = √(1 − r²) · σtotal

This is a coordinate rotation. σtotal points perpendicular to the ridge — it's the well-constrained direction the data pins down tightly. r points along the ridge — it's the weakly-constrained direction the data barely cares about. After reparameterization, every MCMC proposal naturally decomposes into these two orthogonal directions.

Proposal geometry: before vs after reparameterization

Before: (σz, σbase)

Proposal axes aligned with coordinate grid. Most moves cross the ridge perpendicular → rejected. Chain wastes most of its K=5 rejuvenation moves fighting geometry. Acceptance ≈ 5–15%. Marginal estimates smeared along the ridge.

After: (σtotal, r)

Proposal axes aligned with the likelihood geometry. σtotal perturbations test real signal (accepted/rejected on merit). r perturbations explore freely (data doesn't care). Every move is useful. Acceptance ≈ 25–40%. Tight, accurate posteriors.

The Full Learned Parameter Vector

The system learns four parameters: ρ (the AR(1) persistence of the latent regime dynamics), σtotal (the total vol-of-vol, well-identified by data), μbase (the base mean level of the log-volatility curve), and r (the vol-of-vol split ratio, weakly identified). Every CUDA kernel that needs the physical volatility parameters derives them on-the-fly: σz = r · σtotal and σbase = √(1 − r²) · σtotal. The derivation costs two multiplications and one square root per thread block — negligible overhead for the geometric benefit it provides to the CPMMH proposals.

07 — CPMMH Rejuvenation

Correlated Noise Makes Replay Cheap

Standard PMMH (Particle Marginal Metropolis-Hastings) proposes a new θ* and runs a completely fresh particle filter to estimate its log-likelihood. The problem: two independent particle filter runs produce noisy likelihood estimates, and the noise in the MH ratio causes excessive rejections — even when θ* is close to θ.

CPMMH (Correlated PMMH) solves this by reusing most of the same random numbers. If the current filter used noise εt at each step, the proposed filter uses:

ε*t = ρcorr · εt + √(1 − ρcorr²) · εfresh where ρcorr = 0.99

With a correlation coefficient of 0.99, the proposed trajectory shares 99% of its randomness with the current one. The two particle filter runs produce nearly identical trajectories, which means their log-likelihood estimates are highly correlated. The Metropolis-Hastings ratio — the difference of two log-likelihoods — therefore has very low variance. The acceptance or rejection of θ* reflects genuine quality of the proposed parameters rather than Monte Carlo noise artifacts. This is the key insight of Deligiannidis, Doucet, and Pitt (2018): by correlating the noise, you make the pseudo-marginal ratio behave almost like an exact ratio, even though each individual likelihood estimate is still noisy.

Fixed-Lag Replay with Circular Buffers

Full replay from t=0 would be O(T) per rejuvenation — impossibly expensive. Instead, we checkpoint the inner filter state every L=200 ticks and only replay the last L observations. The stored noise lives in a circular buffer of size L+64, wrapping via modular arithmetic. This keeps both memory O(Nθ × Ninner × L) and compute O(L) per rejuvenation, independent of total time T.

Circular noise buffer — fixed-lag replay memory

The noise buffer wraps circularly with capacity L+64 slots. Each timestep writes its random variates to position t mod capacity, overwriting the oldest data. During CPMMH rejuvenation, the replay reads the last L stored slots to reconstruct the correlated trajectory. This design keeps memory consumption proportional to the lag window rather than the total sequence length. At our working dimensions of Nθ = 1024, Ninner = 512, and L = 264, the buffer occupies roughly 550 MB — comfortably within a single RTX 5080. Without circularity, storing noise for T = 5000 observations would require over 40 GB, far exceeding any single GPU's memory.

Adaptive Proposals via Empirical Cholesky

The CPMMH proposal uses a 95/5 mixture: 95% of the time, it draws from an adaptive multivariate Gaussian whose covariance is the empirical covariance of the current θ-particles (scaled by 2.38²/d, the optimal Haario-Bardenet factor), decomposed via Cholesky. The remaining 5% uses a fixed diagonal proposal to maintain ergodicity. This lets the proposal automatically discover and exploit correlations between parameters.

08 — The RBPF Inner Filter

Rao-Blackwellization: Analytically Integrate What You Can

The inner filter doesn't sample ht directly. Since ht | z̃t, θ is conditionally linear-Gaussian (after the OCSN transformation), we can propagate Kalman sufficient statistics (μh, Vh) in closed form. Each inner particle only samples the nonlinear z̃t regime variable. This is the Rao-Blackwell trick: replacing sampling with exact computation wherever the model structure permits.

RBPF per-particle update cycle — Kalman predict-update on h given sampled z̃

Each inner particle carries three pieces of state: the sampled regime variable z̃, and the Kalman sufficient statistics μh (conditional mean of log-volatility) and Vh (conditional variance). The update proceeds in five stages.

First, the particle samples a new z̃t by propagating the AR(1) dynamics: the previous z̃ is scaled by ρ and perturbed by Gaussian noise scaled by σz. This is the only stochastic step per particle — everything else is deterministic.

Second, the new z̃ is squashed through the tanh mapping to produce z ∈ [0, 3], and the three regime-dependent curves are evaluated: the mean-reversion speed θ(z), the local mean μ(z), and the local volatility-of-volatility σh(z).

Third, the Kalman prediction propagates the sufficient statistics forward. The predicted mean μh− is a weighted average of the previous μh (scaled by the persistence φ = 1 − θ) and the regime mean μ(z) (scaled by θ). The predicted variance Vh− grows by φ² · Vh + σh², reflecting both the uncertainty propagation and the new innovation noise.

Fourth, the Kalman update incorporates the observation. The OCSN linearization means the observation log(yt²) is approximately equal to ht plus a log-χ²(1) error with known mean (−1.27) and known variance (π²/2 ≈ 4.93). The innovation — the difference between what we observe and what we predict — is divided between updating the mean and computing the particle's weight. The Kalman gain determines how much the observation pulls the mean estimate, and the posterior variance Vh shrinks by the factor (1 − K).

Fifth, the log-weight for this particle is accumulated. It equals the log-predictive density: a Gaussian evaluated at the innovation, with variance equal to the predicted variance plus the observation noise. This weight is what the outer SMC² layer uses to score the parent θ-particle's fitness.

Without Rao-Blackwellization, the inner filter would need to sample both z̃t and ht, doubling the state dimension and dramatically increasing variance. The Kalman update is exact given z̃ — no sampling noise. This means the per-particle log-likelihood estimates fed to the outer SMC² layer and to CPMMH are much tighter, which directly translates to better outer weight estimates and higher CPMMH acceptance rates. The RBPF and CPMMH improvements are synergistic: each makes the other work better.

09 — GPU Implementation

CUDA Architecture and Memory Layout

The entire algorithm runs on GPU with a Structure-of-Arrays (SoA) memory layout for coalesced access. The Nθ × Ninner = 524,288 particles are organized so that the RBPF step launches Nθ thread blocks of Ninner threads each. Shared memory holds per-θ-particle data (parameters, reductions), while each thread manages one inner particle.

GPU thread hierarchy — one CUDA block per θ-particle, one thread per inner particle

The mapping from algorithm to hardware is natural and direct. Each of the 1024 parameter hypotheses becomes a CUDA thread block. Within each block, the 512 inner particles become individual threads. This means the RBPF propagation step launches a single kernel with 1024 blocks × 512 threads = 524,288 threads, each of which independently propagates one z̃ sample and updates its Kalman statistics.

The parameter values for each θ-particle — ρ, σtotal, μbase, and r — are loaded once into shared memory by thread 0 of each block, then broadcast to all 512 threads via a synchronization barrier. This avoids 512 redundant global memory reads per block. The physical parameters σz and σbase are derived on-the-fly from the stored reparameterized values in shared memory, which costs only two multiplications and one square root per block — negligible compared to the rest of the kernel.

Memory is organized as Structure-of-Arrays (SoA) rather than Array-of-Structures. All z̃ values across all particles are stored contiguously, then all μh values, then all Vh values, and so on. When 512 threads in a warp read their z̃ values simultaneously, these reads are adjacent in memory and get coalesced into a single memory transaction. With AoS layout, each thread's data would be scattered across a large struct, causing fragmented reads and wasting bandwidth.

Block-level reductions — needed for computing the log-sum-exp of inner weights, the ESS, and the systematic resampling CDF — use warp-level shuffle primitives for the first 32 elements, then shared memory for the cross-warp combination. The CPMMH kernel is the most demanding: it replays L=200 timesteps of the full RBPF cycle within a single kernel launch, reading from the circular noise buffer and writing intermediate state to a scratch particle array until the acceptance decision is made.

10 — Conclusion

Convergence, Sequence Length, and Practical Lessons

Throughout development and testing, one pattern emerged repeatedly: increasing the observation sequence length to T=3000 resolved the majority of parameter recovery failures. At shorter horizons like T=800 or T=1200, the algorithm would sometimes recover ρ and μbase accurately but produce wide or biased posteriors for the vol-of-vol parameters σtotal and r. The identification ridge between σz and σbase — the very problem the reparameterization addresses — requires sufficient data to constrain even the well-identified σtotal direction tightly enough for the CPMMH moves to lock onto the correct basin.

The reason is statistical, not algorithmic. The stochastic volatility model has a deep hierarchy: the observations yt are only indirectly informative about the parameters through the latent log-volatility ht, which itself is only indirectly driven by the regime variable z̃t, whose dynamics depend on ρ and σz. Each layer of latent structure acts as a noise bottleneck. With T=1200 observations, the effective information about the deepest parameters — particularly how the total vol-of-vol should be split between σz and σbase — is modest. At T=3000, the cumulative evidence from thousands of regime transitions gives the CPMMH rejuvenation enough signal to navigate the posterior landscape confidently. Acceptance rates climb from 15–25% to a stable 30–40%, resampling events become less frequent, and the posterior standard deviations on all four parameters shrink to the point where z-scores against truth consistently fall below 2.

This is a fundamental property of the model, not a limitation of the algorithm. Any method attempting to learn these parameters online — whether SMC², batch MCMC, or variational inference — would face the same information bottleneck at short horizons. The algorithm's job is to make optimal use of whatever information is available, and the combination of RBPF (for tight likelihood estimates), CPMMH (for efficient rejuvenation), and the (σtotal, r) reparameterization (for geometrically aligned proposals) ensures that the system converges as quickly as the data permits.

For production deployment on streaming HFT data, the practical recommendation is to use a warm-up period of roughly 2000–3000 ticks before trusting the parameter estimates for downstream decisions. During this warm-up, the outer ESS will trigger multiple rounds of resampling and CPMMH rejuvenation, progressively sharpening the posterior. After warm-up, the system tracks parameter drift online with single-tick latency, adapting to regime changes as they unfold in the market.

The three innovations documented here — embedding an RBPF inside the SMC² inner filter, using CPMMH for rejuvenation instead of standard PMMH, and reparameterizing the vol-of-vol channels into orthogonal (σtotal, r) coordinates — are individually well-motivated but their power comes from the interaction. The RBPF produces low-variance likelihood estimates that make CPMMH's correlated ratio nearly exact. CPMMH's high acceptance rates make the reparameterization's geometric alignment immediately useful rather than merely theoretical. And the reparameterization breaks the ridge that would otherwise waste most of CPMMH's computational budget. Each component amplifies the others. The result is a system that learns stochastic volatility parameters online, in real time, on a single GPU, with the statistical efficiency that previously required batch MCMC on the full dataset.

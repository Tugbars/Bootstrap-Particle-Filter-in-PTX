Convergence Gating

How ParamTracker decides when to push learned parameters to the BPF — and why the naive approach failed catastrophically.

1 The Problem

ParamTracker runs amnesiac SMC² windows — each re-initialized from prior — and fuses their posteriors with a Kalman filter. The 8 estimated parameters control the BPF's volatility model. The question: when do we start pushing Kalman estimates to the BPF?

Push too early

First window's posterior is noisy. Pushing a half-baked μ_base corrupts the BPF's log-volatility center. Every h-estimate is biased until corrected.

Push too late

BPF runs on prior defaults (μ_base = −10) while the Kalman already has −4.5 from window 1. Thousands of ticks of avoidable error.

Push a bad curve

BPF 2D evaluates μ(z) at every particle. A wrong μ_rate corrupts estimates across the entire stress distribution — not just one point.

The goal

Push fast params early (the Kalman handles noise), hold curve params until the data actually identifies them, and never revert once committed.

2 Why R̂ Alone Failed

First attempt: compute R̂ across the rolling buffer of window posteriors. If windows agree (R̂ < 1.5), push Kalman. Otherwise hold prior default.

Result: μ_base stuck at −10.0 for 30K+ ticks
The Kalman had −4.08 from window 1 (truth = −4.5). But R̂ never consistently dropped below threshold — amnesiac windows naturally scatter because each explores from prior independently.

The fundamental contradiction: R̂ measures "do windows agree?" The Kalman's job is to fuse windows that don't agree. Requiring agreement before pushing means "only push when the Kalman is redundant."

Worse — when R̂ finally did drop (window 19), the calm→crisis transition at window 24 spiked it back, reverting μ_base to −10.0 after 5 good windows:

3 Tiered Gating with Latches

The 8 parameters have fundamentally different identification requirements. Fast dynamics params (ρ, μ_base) are identifiable from any data. Curve shape params (μ_rate, σ_scale) require stressed data to be identified. The gating must respect this.

GATE_KALMAN_MIN ρ · σ_total · r_split · μ_base
Logic

Push Kalman estimate after min_windows (default: 2). No R̂ check. One-way latch — once converged, stays converged forever.

Why

Any data identifies these. The Kalman has a useful estimate after 2 windows. Holding at prior default is expensive — μ_base = −10 vs truth = −4.5 is a 5.5 log-vol unit error.

if converged[i] != 1 and n_windows >= min_windows: converged[i] = 1 // one-way latch, never reverts
GATE_RHAT_LATCH μ_scale · μ_rate · σ_scale · σ_rate
Logic

Wait for R̂ to drop below threshold (1.5). When it does, latch converged=1 permanently. Never reverts, even when R̂ spikes later.

Why

Wrong curve shapes systematically corrupt BPF 2D across the entire z-distribution. Worth waiting for window agreement. The latch prevents calm periods from reverting valid crisis-learned estimates.

if converged[i] != 1 and rhat_report.ready and rhat[i] < threshold: converged[i] = 1 // one-way latch, never reverts
GATE_LOCKED any param not freed by phased ratchet
Logic

Always push prior default. Set automatically by set_free_mask() for locked params. When a param becomes free, it transitions to the appropriate mode.

Why

SMC² isn't estimating this parameter yet — it's fixed internally. Pushing a default is the only safe option. The phased ratchet decides when to free params based on z-range.

converged[i] = -1 // always locked, push prior_default[i]

4 The Snapshot Push

After each window, the gating logic builds the parameter vector that the BPF actually sees:

for each param i: switch gate_mode[i]: GATE_KALMAN_MIN: if not converged and n_windows >= min_windows: converged[i] = 1 // latch GATE_RHAT_LATCH: if not converged and R̂[i] < 1.5: converged[i] = 1 // latch GATE_LOCKED: converged[i] = -1 // always locked // Build gated vector for each param i: gated[i] = converged[i] == 1 ? kalman.x[i] // learned : prior_default[i] // safe fallback // BPF sees gated[], Kalman sees raw posteriors (always) snap.theta = gated
Key invariant: The Kalman always updates internally, regardless of gate state. It accumulates information silently. The gate only controls what the BPF sees — it never blocks learning.

5 Phase Transitions

The phased ratchet monitors z-range and unlocks params as more of the stress distribution becomes observable. Each set_free_mask() call triggers gate mode transitions:

Param Phase 1 Phase 2 Phase 3
ρ KALMAN_MIN → latch at win 2 latched ✓ latched ✓
σ_total KALMAN_MIN → latch at win 2 latched ✓ latched ✓
r_split KALMAN_MIN → latch at win 2 latched ✓ latched ✓
μ_base KALMAN_MIN → latch at win 2 latched ✓ latched ✓
μ_scale LOCKED prior default RHAT_LATCH wait for R̂ < 1.5 latched ✓
μ_rate LOCKED prior default RHAT_LATCH wait for R̂ < 1.5 latched ✓
σ_scale LOCKED prior default LOCKED prior default RHAT_LATCH wait for R̂ < 1.5
σ_rate LOCKED prior default LOCKED prior default RHAT_LATCH wait for R̂ < 1.5

When set_free_mask() frees a previously locked param, it automatically sets the gate mode: KALMAN_MIN for indices 0–3, RHAT_LATCH for indices 4–7. Already-latched params are never touched — the latch is permanent.

6 Production Timeline

Window 1 — Cold start

All 8 params gated. BPF runs on prior defaults. Kalman initializes from first SMC² posterior.

μ_base pushed = −10.0 (prior) · Kalman internal = −4.08 · truth = −4.5

Window 2 — KALMAN_MIN latch

Phase 1 params (ρ, σ_total, r, μ_base) latch. BPF immediately improves.

μ_base pushed = −4.59 (Kalman) · one-way latch: never reverts

Windows 3–8 — Learning continues

Kalman fuses more windows, estimates tighten. R̂ fluctuates but doesn't matter — KALMAN_MIN ignores it.

R̂[μ_base] = 3.97 at window 9 — would have reverted under old design. Latch holds.

Window 8 — Phase 2 transition

Phased ratchet sees z_max > threshold. Frees μ_scale, μ_rate in SMC² and gating. Gate mode: LOCKED → RHAT_LATCH.

converged[4] = 0, converged[5] = 0 · BPF still uses prior defaults for these

Windows 9–10 — Curve exploration

SMC² explores μ_scale, μ_rate with stressed data. Windows scatter — R̂ is high (8.14, 3.20). Gate holds prior defaults. Safe.

Window 11 — RHAT_LATCH fires

R̂ drops below 1.5 for both curve params (0.94, 0.76). Latch fires. BPF 2D starts using learned curve shape.

μ_scale: gated=3.066 (truth=3.0) · μ_rate: gated=0.516 (truth=0.5)

Windows 20+ — Calm period

R̂ for μ_scale spikes to 2.36 (no stressed data to identify it). Old design would revert to prior defaults. Latch holds — 6/6 converged throughout.

Kalman continues tracking internally. Curve estimate from crisis persists.

7 The Latch Principle

Both gate modes use one-way latches. Once converged[i] = 1, it stays 1 forever. This is the same principle as the phased learning ratchet: information, once gained, is never discarded.
